\begin{abstract}
Person re-identification ranks gallery photographs so that other views of the person in a query crop come first.
This paper measures how inference-time patch selection, pruning depth, and the number of retained tokens change retrieval accuracy and measured latency in a frozen CLIP-ReID ViT-B/16 encoder.
The encoder is not retrained.
Selection, when used, runs after a complete transformer block.
The class token is kept, surviving patches stay in their original spatial order, and the later blocks run on that shorter sequence.
No discarded token is fused back, and no pruning weight is learned.
On the official Market-1501 test the full encoder scores 89.41\% mAP and 94.98\% Rank-1, an approximate reproduction of the published 89.6\% and 95.5\%.
Keeping the 64 patches most attended by the class token after block 6 lowers that test to 74.86\% mAP and 88.93\% Rank-1.
Keeping 96 patches after block 9 scores 89.27\% mAP and 95.13\% Rank-1.
At both settings, five random patch selections score below the class-attention rule.
A Tesla T4 timing run does not establish a speedup: at batch 32 the full encoder's own trial medians move from 241.5\,ms to 313.7\,ms.
The patch figure shows one query only.
\end{abstract}

\section{Introduction}
A re-identification system receives one cropped person and a gallery collected by other cameras.
Its output is an ordering, not an identity in a closed set.
Market-1501 made this protocol standard: 751 people for training, 750 disjoint people for testing, and a fixed rule for which gallery hits count \cite{zheng2015market}.
CLIP-ReID later showed that a CLIP image encoder, adapted without requiring a text label at inference, is a strong ranker on that benchmark \cite{li2023clipreid,radford2021clip}.

The encoder is a vision transformer \cite{dosovitskiy2021vit}.
A $256 \times 128$ crop is divided into 128 patches.
Those patches, together with one class token, pass through all 12 layers, but the vector used for search is built only from the class token.
The patch tokens are therefore computed in full and then discarded, except for the information they have already written into the class token through attention.
Token pruning asks whether the later layers need every patch \cite{liang2022evit}.

The question is not whether a shorter sequence can beat the published model.
For this frozen encoder, how do inference-time patch selection, the block at which the cut is made, and the number of retained patches change retrieval accuracy and measured inference cost?
Two cuts are measured.
After block 6 the class token keeps 64 of 128 patches.
After block 9 it keeps 96.
The second cut was fixed from a validation comparison before the official-test scores in this revision were used, and it was not changed afterward.
A uniform random selection at the same block and the same patch count is the control.
The result is a measurement, not a new pruning algorithm and not a complete reproduction of EViT.

\section{Related work}
Market-1501 collects six cameras in an outdoor campus scene and evaluates single-query search after removing junk detections and same-camera matches of the query identity \cite{zheng2015market}.
The numbers below use that protocol and do not add the optional 500{,}000 distractors.

CLIP-ReID starts from CLIP's image tower and learns re-identification prompts and an image encoder on the training split \cite{li2023clipreid}.
The published ViT result without side-information embeddings or overlapping patches (OLP) is 89.6\% mAP and 95.5\% Rank-1.
This project loads that released ViT-B/16 checkpoint and does not repeat its training.
Camera side-information embeddings are off, matching the published row used for comparison.

A vision transformer mixes a class token with a grid of patch tokens \cite{dosovitskiy2021vit}.
EViT showed that the class token's attention is a usable score for discarding patches, and that the later blocks can run on the reduced sequence \cite{liang2022evit}.
That work trains and evaluates the idea on image classification.
The experiment here copies the selection rule, applies it once at inference, and measures person re-identification instead of classification accuracy.
No pruning weights are learned.

k-reciprocal re-ranking is a feature-space method from 2017 \cite{zhong2017kreciprocal}.
It was run on the first full-encoder and block-6 measurements, with neighborhood sizes $k_1{=}20$, $k_2{=}6$, and mixture weight $0.3$.
The CLIP-ReID code uses a larger neighborhood; that variant is not substituted.
k-reciprocal does not see the image tokens.
It was not run on the block-9 setting or on the random controls reported below.

\section{Method}
\subsection{Unpruned ranking}
Each crop is resized to $256 \times 128$ and encoded by the CLIP-ReID ViT-B/16, with patch size 16, stride 16, and camera side-information embeddings switched off.
The patch grid is $16 \times 8$, so the sequence length is $128 + 1 = 129$.
The search vector is the concatenation of the batch-normalized class token and the batch-normalized projection of that token, an $\ell_2$-normalized vector of 1{,}280 dimensions.
For a query vector $q$ and a gallery vector $g$, the score is the cosine
\begin{equation}
v = q^{\top} g.
\end{equation}
Gallery entries whose filename marks them as junk are removed before ranking.
A gallery photograph of the same person taken by the same camera as the query is ignored when mAP and Rank-$k$ are computed.

\subsection{Where the tokens are cut}
Pruning, when used, happens after a complete transformer block.
The class token is always kept.
The retained patches are gathered in their original left-to-right, top-to-bottom order, and the remaining blocks run on that shorter sequence.
Position vectors are added once, before block 1, and are not recomputed.
The search vector is still the 1{,}280-dimensional normalized descriptor from the class token.
Batch-normalization running statistics stay at the values stored in the checkpoint.
The same selection settings are used for every query and every gallery image.

Two selectors are compared.
Class attention scores each patch by the class token's attention, averaged across heads after the softmax, and keeps the highest scores.
A tie keeps the earlier spatial index.
The reference implementation obtains those scores from a separate attention call with weights enabled.
That extra call is part of the measured cost.
A second implementation reads the class-token row directly.
It is reported only as an implementation comparison in the timing run.
It is not substituted for the reference scores in the accuracy tables.
Random selection draws the same number of patches uniformly, without replacement.
The draw for an image is fixed by the experiment seed and a hash of that image's preprocessed pixels.
It does not use the label, and it does not compute attention weights.
The accuracy seeds are 11, 23, 37, 53, and 71.

The two cuts are after block 6, keeping 64 patches, and after block 9, keeping 96.
The second was the additional configuration with the highest validation mAP in an earlier attention comparison.
It was not chosen or changed using the official-test scores below.
The checkpoint is frozen.
There is no learned pruner and no fusion of discarded tokens.

\section{Discussion}
The checkpoint, the descriptor, and the Market-1501 metric stay fixed.
What changes is the token sequence: which patches continue, after which block, and how many.
On the official test, discarding 64 patches after block 6 costs 14.55 points of mAP and 6.06 points of Rank-1.
Discarding 32 patches after block 9 changes the same test by 0.14 points of mAP downward and 0.15 points of Rank-1 upward.
That second difference is small, and the setting was not chosen on the official test.
Cost in those sentences means retrieval accuracy.
It is not the latency in Table~\ref{tab:time}.

Class attention is above the five-seed random mean at both cuts.
The gap is larger when 64 patches remain after block 6 than when 96 remain after block 9.
The sample standard deviation describes seed-to-seed variation on one fixed split.
It does not describe a new set of people.

Rank-10 stays high under the block-6 cut, so a true match is still usually inside the first ten allowed gallery images.
That does not show that identity information sits only in the retained patches.
By the pruning block, the class token and the patch tokens have already mixed.
Figure~\ref{fig:prune} is one query.
k-reciprocal, on the earlier files only, recovers much of the block-6 mAP without looking at tokens.
It was not rerun for block 9 or for the random controls, so those rows cannot be compared with it.

The timing result is separate.
At batch 1 the attention paths are faster than the full encoder in all three trials, by about 1.5\,ms.
At batch 32 the full encoder's own medians already differ by more than 70\,ms.
A ratio against that moving baseline is not an established speedup.
The class-token-row implementation is a timing comparison only.
Accuracy tables use the reference attention scores.

The limits are specific.
Only two cuts were measured, both chosen before the official-test comparison.
The paper does not claim that block 9 or 96 patches is the best operating point.
The checkpoint was not fine-tuned after the rule was inserted.
The selection rule is the class-attention rule from image classification \cite{liang2022evit}, applied once after a complete block, without the training or token fusion used by EViT.
The contribution is the measurement on person re-identification.

\section{Conclusion}
A frozen CLIP-ReID checkpoint approximately reproduces the published Market-1501 operating point, at 89.41\% mAP and 94.98\% Rank-1.
After block 6, keeping the 64 patches most attended by the class token scores 74.86\% mAP and 88.93\% Rank-1 on all 3{,}368 queries.
The accuracy cost of that removal is 14.55 points of mAP.
After block 9, keeping 96 patches scores 89.27\% mAP and 95.13\% Rank-1.
Five random seeds at each cut score below the matching class-attention row.
The Tesla T4 timings do not establish a speedup.
The patch figure shows one query only.
